Phase 1: Cloud-MAE Architecture Redesign (ออกแบบ MAE ให้ Transfer ได้ทุก Fusion)
หัวใจของการแก้ปัญหา Issue #1 ใช้หลักการ "Shared Backbone, Modality-Split Input":

Input S1 (2ch) ──┐
                  ├─→ PatchEmbed (9ch) ─→ ViTEncoder Backbone (Shared)
Input S2 (7ch) ──┘                            │
                                               ↓
                               MAE Decoder (ทิ้งหลัง Pretrain)
                                               │
                                        Reconstruction Loss
                                    (MSE เฉพาะส่วนที่ถูกเมฆบัง)
วิธี Transfer Weight ไปยัง 3 Fusion Models:

Early Fusion: Copy ViTEncoder ทั้งก้อน (Transformer Blocks) ตรงๆ เปลี่ยนแค่ PatchEmbed ที่รับ input (9ch → 9ch ตรงเลย)
Late Fusion: Copy ViTEncoder Transformer Blocks ไปให้แต่ละ Branch ปรับ PatchEmbed ของแต่ละ Branch แยก (S1=2ch, S2=7ch)
Cross-Attention: เหมือน Late Fusion แต่เพิ่ม Cross-Attention Layer ระหว่าง S1→S2 Features
นี่คือวิธีที่มีงานวิจัยรองรับ ได้แก่ DINO, SatMAE, และ SpectralGPT ซึ่งทุกงานใช้เทคนิค "Freeze Backbone + Finetune Patch Projection" เพื่อ Transfer ระหว่าง Input ที่ต่างช่องสัญญาณกัน

Phase 3: Cloud-MAE Pretraining (เทรน Backbone หลัก)
Input: (S1=2ch + S2=7ch) stacked = 9ch, 256×256
Cloud Mask: Block Masking 50-75% บน S2 เท่านั้น (S1 ไม่ถูกบัง)
Loss: MSE เฉพาะ Masked Pixels ของ S2
Output: cloud_mae_backbone.pth (Shared ViT Encoder Weights)
เวลาประเมิน: ~2-3 ชั่วโมง (100 Epochs, Batch 16, BFloat16)
