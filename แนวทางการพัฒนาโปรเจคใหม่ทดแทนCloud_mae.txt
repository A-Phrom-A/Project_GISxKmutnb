# ส่วนที่ 2: คำถามวิจัยและสมมติฐาน (ปรับใหม่)

**คำถามหลัก:** โมเดล ViT ที่เรียนความสัมพันธ์ข้าม band (cross-band relationships) กู้คืน S2 ที่หายไปได้ดีกว่าวิธีไม่ใช้การเรียนรู้ความสัมพันธ์หรือไม่ และ S1 มีส่วนช่วยแค่ไหน

- **RQ1:** ViT กู้คืน band ได้แม่นกว่า RF baseline หรือไม่ เมื่อ band หายไปในรูปแบบต่างๆ
- **RQ2:** การมี S1 ลดความคลาดเคลื่อนได้เท่าไร และขึ้นกับจำนวนและชนิด band ที่หายไปอย่างไร
- **RQ3:** (xAI) ขนาดและทิศทางอิทธิพลของ S1 (VV, VH) เทียบกับ band S2 ที่เหลือเป็นอย่างไร
- **RQ4:** Band ที่กู้คืนมา ใช้งานต่อใน palm segmentation ได้ดีแค่ไหน

ยังคงหลักเดิมไว้ คือ **ไม่ตั้งสมมติฐานว่า S1 ต้องช่วยเสมอ** ให้ผลทดลองบอกเอง

# ส่วนที่ 3: แผนทั้งหมดตามขั้นตอน

## 3.1 รวบรวมข้อมูล

- ใช้ชุดข้อมูลเดิมใน repo: S1 (VV, VH), S2 (B2, B3, B4, B5, B8, B11, B12) และ GEO-Sat (RGB)
- **ตัดสินใจเรื่อง GEO-Sat:** แนะนำให้ **ไม่ใส่ในการทดลองหลัก** เพราะเป็น optical RGB ที่ซ้ำกับ B2/B3/B4 จะปนเปื้อนการวัดอิทธิพลของ S1 ถ้าอยากใช้ ให้ทำเป็นการทดลองเสริมแยกต่างหาก
- เก็บภาพ S2 ที่ **เมฆน้อยหรือไม่มีเมฆ** เป็นค่าจริง (ground truth) และจับคู่กับ S1 ที่ถ่ายใกล้กันที่สุด
- ควรมีอย่างน้อย 2-3 พื้นที่หรือช่วงเวลาที่ต่างกัน เพื่อทดสอบการ generalize
- บันทึกข้อมูลกำกับ (metadata): วันที่ถ่าย, ช่องว่างเวลาระหว่าง S1 กับ S2, พื้นที่, ชนิดการใช้ที่ดิน

## 3.2 จัดการข้อมูล

ใช้ `lib1_fusion/preprocessor.py` เป็นฐาน และเพิ่มสิ่งต่อไปนี้

1. **จัดกริดให้ตรงกัน:** reproject และ resample ทั้งหมดไปกริดเดียวกัน (เช่น 10 m) B5, B11, B12 ของ S2 เดิมเป็น 20 m ต้องบันทึกวิธี resample ไว้
2. **ปรับค่า S1:** แปลงเป็น dB, ทำ speckle filtering (เช่น Lee filter) และบันทึกว่าทำอะไรไว้ เพราะมีผลต่อผลสรุป
3. **ปรับค่า S2:** ใช้ L2A surface reflectance, clip outlier แล้ว normalize ต่อ band จากสถิติของชุดฝึกเท่านั้น
4. **ตัดเป็น tile** เช่น 64×64 หรือ 128×128 พิกเซล
5. **แบ่งชุดข้อมูลตามพื้นที่ (spatial block split)** เป็น train / val / test ห้ามสุ่มรายพิกเซล เพราะพิกเซลข้างเคียงมีค่าใกล้กัน จะเกิด data leakage
6. กรอง tile ที่มีเมฆหรือค่า NaN ออกจากค่าจริงของ S2

## 3.3 โมเดล

**โมเดลหลัก: ViT จาก `lib2_vitpalm`**

README ระบุว่า Cloud-MAE ใช้ masked autoencoding อยู่แล้ว แต่ผมยังไม่ได้ดูโค้ด ถ้าเป็นการปิดบังแบบ patch (spatial) ต้องเพิ่ม **channel-wise masking** คือสุ่มปิดทั้ง band ตามเซตที่กำหนด แล้วให้โมเดลสร้างค่าของ band นั้นกลับมา สิ่งที่ต้องทำ

- เพิ่ม **channel embedding** ให้แต่ละ band (เพื่อให้โมเดลรู้ว่ากำลังเห็น/ขาด band ไหน)
- เพิ่ม **reconstruction head** ที่ออกค่า band ที่ขาด
- ใช้ loss เฉพาะ band ที่ถูกปิด (เช่น L1 หรือ MSE)

**ชุดโมเดลที่ต้องเทรน (น้อยตัว)**

| โมเดล | อินพุต | ใช้ตอบอะไร |
|---|---|---|
| M1: ViT-S2only | S2 ที่เหลือ | baseline ของ ViT |
| M2: ViT-Fusion (**ตัวหลัก**) | S1 + S2 ที่เหลือ โดยสุ่มซ่อน S1 บางรอบ (modality dropout) | ตัวที่ใช้ SHAP และเทียบกรณีมี/ไม่มี S1 |
| B1: Random Forest | S1 + S2 ที่เหลือ | baseline ตามแผนเดิม |

**การสุ่มปิด band ตอนเทรน:** สุ่มจำนวน band ที่ปิดตั้งแต่ 1 ถึง 7 แล้วสุ่มว่า band ไหน เพื่อให้โมเดลเดียวรับได้ทุก pattern

**เรื่อง RF:** RF รับ input ขนาดคงที่ ถ้าจะให้ครอบคลุมทุก pattern ต้องเทรน RF แยกต่อ pattern หรือใช้การเติมค่าที่ขาด ซึ่งช่วยแสดงจุดอ่อนข้อหนึ่งของ baseline ได้ดี แนะนำให้เทรน RF เฉพาะชุดย่อยที่เป็นตัวแทน (เช่น pattern ที่ปิด 1, 2, 3, 5, 7 band อย่างละไม่กี่แบบ) ไม่ต้องครบ 127

**เรื่อง Apriori / Eclat:** แนะนำให้ย้ายไปเป็น **ภาคผนวก (optional)** เพราะต้องแปลงค่าเป็นช่วง (discretize) ทำให้เสียความละเอียด เทียบกับโมเดลต่อเนื่องไม่เป็นธรรม และไม่ตอบโจทย์ใหม่เรื่อง cross-band learning ถ้าอาจารย์หรือโจทย์ยังต้องการ ให้เก็บไว้เป็นตัวเปรียบเทียบเชิงกฎ แต่นี่คือการตัดสินใจของคุณ

## 3.4 การทดสอบ (Evaluation)

**ส่วนนี้ใช้การ inference ล้วน ไม่ต้องเทรนใหม่**

- ใช้ชุด test (คนละพื้นที่กับชุดฝึก)
- วน **127 pattern × 2 กรณี (S1 เปิด/ปิด)** กับ M2 (และ M1, B1 ตามที่กำหนด)
- กรณี S2 ปิดหมดทุก band:
  - S2-only → ไม่มี input จึงไม่ประเมิน หรือใช้ค่าเฉลี่ยของชุดฝึกเป็น baseline
  - S1+S2 → รายงานเป็นผล SAR→Optical translation แยกต่างหาก

**ตัวชี้วัด**

| ตัวชี้วัด | ใช้ทำอะไร |
|---|---|
| MAE, RMSE (แยกรายแต่ละ band ที่กู้) | ความคลาดเคลื่อน |
| SSIM / PSNR | คุณภาพเชิงโครงสร้างของภาพ |
| Recovery rate | สัดส่วนพิกเซลที่ผ่านเกณฑ์ที่กำหนดล่วงหน้า |
| ΔMAE = MAE(ไม่มี S1) − MAE(มี S1) | ตัววัดประโยชน์ของ S1 (เหมือนแผนเดิม) |
| Runtime / Memory | เปรียบเทียบความคุ้มค่า |

ต้อง **กำหนดเกณฑ์ผ่าน/ไม่ผ่านก่อนดูผล** และรายงานความไม่แน่นอน เช่น bootstrap confidence interval โดย resample ระดับ tile หรือ spatial block (ไม่ใช่ระดับพิกเซล) และรันซ้ำหลาย random seed

## 3.5 การวิเคราะห์ xAI (SHAP)

นี่คือหัวใจของแนวคิดที่พี่ Want เสนอ ใช้โมเดล M2 ที่ดีที่สุดเพียงตัวเดียว

**วิธีทำ**

1. เลือกเครื่องมือ: GradientSHAP หรือ DeepSHAP (ใช้ผ่าน Captum หรือ shap) เพราะ KernelSHAP ช้าเกินไปกับ ViT
2. **จัดกลุ่ม feature ระดับช่อง (channel-level attribution):** รวมค่า SHAP ของทุกพิกเซลในแต่ละ channel ให้เหลือ 1 ค่าต่อ channel ต่อ tile (S1-VV, S1-VH, B2, B3, ...) เพื่อให้เทียบกันได้
3. คำนวณ **ค่า mean |SHAP|** ต่อ channel แล้วแยกวิเคราะห์ตาม
   - band เป้าหมายที่กำลังกู้
   - จำนวน band ที่ปิด
   - ชนิดพื้นผิว (พืช, น้ำ, ดิน เป็นต้น)
4. รายงาน **ทิศทาง** ด้วยสัญญาณของ SHAP (ค่าสูงของ VV ดันค่า B8 ที่ทำนายขึ้นหรือลง)
5. รายงานสัดส่วน เช่น "S1 (VV+VH) มีส่วนร่วม x% ของอิทธิพลรวม เมื่อ band เป้าหมายคือ B8"

**ข้อควรระวัง (ควรเขียนในรายงานด้วย)**

- Feature ที่สัมพันธ์กันสูง (เช่น B2/B3/B4) ทำให้ SHAP กระจายค่าหากัน การเทียบ "กี่เท่า" ต้องระวังการตีความ
- SHAP บอกว่าโมเดลอาศัย feature ไหน ไม่ได้บอกว่าความสัมพันธ์จริงในธรรมชาติเป็นเช่นนั้น
- จึงควรใช้ **ablation ชุดเล็กเป็นตัวยืนยัน** เช่น เลือก 10-15 pattern ตัวแทน แล้วดูว่า ΔMAE สอดคล้องกับอิทธิพลจาก SHAP หรือไม่ ถ้าสอดคล้อง ข้อสรุปจะแข็งแรงขึ้นมาก
- เพิ่ม **permutation importance ระดับช่อง** เป็นการตรวจสอบอีกแบบที่ถูกและเข้าใจง่าย

## 3.6 วิเคราะห์และสรุปผล

1. **ตารางใหญ่:** แถวคือ pattern (127) คอลัมน์คือโมเดล × (มี/ไม่มี S1) × ตัวชี้วัด และสรุปเป็น heatmap
2. **กราฟหลัก**
   - ΔMAE เทียบกับจำนวน band ที่ปิด (1-7)
   - ΔMAE แยกตาม band ที่กู้ (B8 ง่ายหรือยากกว่า B11/B12)
   - อิทธิพล SHAP ของ S1 vs S2 ต่อ band เป้าหมาย
3. **หาเงื่อนไขที่ S1 ช่วยและไม่ช่วย** รวมถึงกรณีที่ S1 ทำให้แย่ลง ต้องรายงานเป็นข้อค้นพบ ห้ามตัดทิ้ง
4. **Downstream test:** นำ band ที่กู้คืนไปป้อนให้โมเดล palm segmentation เดิมใน repo แล้วดู IoU/F1 เทียบกับ (ก) band จริง (ข) band ที่ขาด (ค) band ที่กู้ด้วย S2-only (ง) band ที่กู้ด้วย S1+S2 นี่คือหลักฐานว่าการกู้คืนมีประโยชน์ต่อการใช้งานจริง
5. **ข้อสรุป** ต้องผูกกับสมมติฐาน RQ1-RQ4 และระบุข้อจำกัด เช่น จำนวนพื้นที่ ช่องว่างเวลาระหว่าง S1 กับ S2 และผลของการทำ speckle filter

# ส่วนที่ 5: ลำดับการทำงานที่แนะนำ

1. **เตรียมข้อมูลและ split** ให้เสร็จก่อน (ตรวจ leakage)
2. ทดลองเล็กก่อน: ใช้ band เดียว (เช่น ปิด B8) เทรน M1 vs M2 เพื่อเช็กว่า pipeline ทำงาน
3. ขยายเป็น random masking เต็มรูปแบบ แล้วเทรน M1, M2 และ B1
4. รันการประเมินครบ 127 pattern × 2 กรณี
5. วิเคราะห์ SHAP บน M2 และทำ ablation ยืนยันชุดเล็ก
6. ทำ downstream test กับ palm segmentation
7. สรุปผลและเขียนรายงาน

**ความเสี่ยงหลักที่ควรรู้ล่วงหน้า**

- ถ้าข้อมูลมีพื้นที่น้อย ผล generalization จะอ่อน ควรมีพื้นที่ทดสอบที่ไม่เคยเห็นตอนเทรน
- ถ้าช่องว่างเวลาระหว่าง S1 กับ S2 ใหญ่ (โดยเฉพาะพื้นที่เกษตรที่เปลี่ยนเร็ว) S1 อาจช่วยได้น้อยโดยไม่เกี่ยวกับตัวโมเดล
- ผลของ SHAP ที่ได้จาก M2 ตัวเดียวอาจไวต่อ random seed ควรทำซ้ำอย่างน้อย 3 seed

ถ้าคุณส่งโค้ดใน `lib2_vitpalm/model` มาให้ดู ผมช่วยระบุได้ว่าต้องแก้ตรงไหนบ้างเพื่อเพิ่ม channel-wise masking และ reconstruction headถ้าอยากให้ผมจัดแผนนี้เป็นเอกสารสำหรับเก็บไว้หรือส่งต่อให้อาจารย์/ทีมต่อ บอกได้เลยครับ
